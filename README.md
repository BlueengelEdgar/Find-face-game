# 寻找人群 V0.6 审核草稿

在原 Phaser 3 + Vite 项目上迭代。限时挑战、时间反馈与自然排列已实现；180/200人正式关卡仍待资源、空间方案及人工视觉确认。未合并或自动发布。

## 玩法与反馈

- 第一关5人教学关；每批5个目标，角标1～5可任意顺序寻找。
- 每关30秒，在规则提示和3、2、1、GO全部结束后启动。找对立即+3秒（不封顶），找错立即−2秒；同一次持续触摸只判定一次，空白、已找到人物及锁定期间不扣时。
- 14px时间条按实际剩余时间显示绿（>20秒）、黄（>10秒）、红（>0秒）；加时可逆向恢复颜色。数字可超过30秒，条宽最多100%。
- 找对时保留勾号与同步放大效果，目标卡片喷发16颗星星（整批最后一人20颗），绿色+3s沿弧线飞向时间条；找错保留红叉/振动及红色−2s飞字。所有飞字独立、数值立即生效。
- 每批切换约700ms，期间停表并锁输入。最后一批完成后庆祝；时间归零立即失败，显示 TIME’S UP! / TRY AGAIN! 与 RETRY。重试当前关卡并重新倒计时。
- 胜利保留 CONGRATULATIONS! / LEVEL COMPLETE!，第一关只有 NEXT LEVEL，第二关显示剩余时间、用时和明确标注的模拟排行榜。

## 人群与验收限制

当前main原有第二关是75/45人，而非150人。V0.6在这些可完成规模上使用独立二维采样、遮罩校正的自然排列，不是网格微偏移；在候选上再放大2.5%，保留既有尺寸下限。资源库的150张漫画人物与本地背景保持不变。

150人实际失败诊断、180/200人容量估算和缺失的30/50张美术资源详见 [V0.6测试报告](docs/V06-VALIDATION.md)。估算不等于真实180/200人试玩验证，未复制头像冒充新人，未擅自缩成小图标或进一步减少人数。

固定视野、动态视口高度与安全区适配保持；视口改变不替换本局身份或队列，过短视口会暂时阻止游戏以保护构图，恢复后继续。后台与批次动画停表。真实Safari工具栏、触摸精度和设备性能仍需人工测试。

## 开发与测试

使用Node.js 22+（云环境24.19.0）：

```sh
npm ci
npm run dev
npm test
npm run build
npm run test:browser
```

开发路径 `/Find-face-game/`。浏览器脚本使用Playwright和云环境的 `/usr/bin/chromium`；Chromium模拟不代表真实iPhone Safari。

- `npm test`：时间状态、胜负、奖励/惩罚、颜色阈值与逆向恢复、暂停、队列及资源回归。
- `npm run test:browser`：实际canvas与触摸、颜色恢复、星星越界、失败重试、当前两关全部完成、四种视口与离线文档。
- `npm run test:offline`：只测完全断网的自包含HTML，先构建。
- `npm run test:capacity`：150人诊断及180/200人容量估算；额外需要Python Pillow/NumPy，这些不是游戏或Pages构建依赖。
- `npm run build`同时生成 `dist/find-crowd-v06.html`；`python scripts/package-trial.py`可生成离线审核ZIP。

历史V0.4/V0.5测试脚本保留作记录，不适用于本版计时规则。

## 结构与发布

`src/model.js`管理唯一队列和限时状态；`src/time-rules.js`提供时间配置与阶段；`src/feedback-effects.js`管理不拦截触摸的独立特效层；`src/match-feedback.js`同步目标与人物放大。布局、漫画资源、背景继续独立于交互逻辑。

保留Vite base `/Find-face-game/` 与既有GitHub Pages工作流，不更改公开状态、权限，不自动合并或部署。人工审核合并后，再通过原Pages地址验收。
