# 寻找人群 · V0.3 第一阶段视觉验收

基于最新 main 的现有 Phaser 3 + Vite 工程迭代。本分支仅实现第一阶段：10 个独立 PNG 插画人物与可交互第一关。**美术尚待人工确认，未进入 30～40 人样板与 150 人扩展。**

## 本地查看
需要 Node.js 22+（测试环境 24.19.0）。
```sh
npm ci
npm run dev
```
打开开发服务器的 `/Find-face-game/`。使用当前检出目录，不需要 Git worktree。不部署公开预览。

## 本阶段行为
每批寻找 5 人，全部完成后换批，10 人分两批通关；原位变暗打勾、错误仅反馈、计时、暂停、重开、结算和明确标注的模拟排行榜保留。
顶部返回按钮打开关卡菜单并暂停，返回游戏后保持暂停，点击继续再计时。
150 人关卡数据和旧算法仍保留在 levels.js，V0.3 后续关卡入口暂不可选；没有用旧 SVG 补足正式角色，也没有把正式第二关偷偷改为 30 人。待阶段验收后继续。

## 美术与布局
- `public/art/v03/character-001.png … character-010.png`：10 个独立透明插画文件，不带编号。
- `src/characters.js`：唯一人物 ID、资源地址与面部锚点；目标和墙体共用同一 PNG。
- `src/art-layout.js`：可复现的手工错位构图、尺寸与前后层级。
- `src/scene.js`：按层级绘制，使用图片 alpha 逐像素命中，不拦截透明矩形。
- `src/main.js`、`src/model.js`：UI 流程与原有规则模型保持独立。
- `src/style.css`、`index.html`：顶部返回/关卡/计时/暂停、中部人群、底部五目标；dvh 与安全区域适配，无页面滚动。

完整规格、来源、人工验收点和后续阶段说明见 [V03-ART-REVIEW](docs/V03-ART-REVIEW.md)。

## 验证命令
```sh
npm test
npm run build
npm run test:browser
```
浏览器测试使用系统 `/usr/bin/chromium`，要求本地 5173 端口空闲。四种视口：390×844、320×568、768×1024、1440×1000。
测试实际 PNG 的面部可见率与透明重叠命中、第一关触摸通关、两批目标资源一致性、错误反馈、暂停/重开、返回菜单和 UI 边界。
`tests/browser.js` 保留为 V0.2 两关历史回归脚本，不适用于当前第一阶段关卡门禁；本阶段执行 `tests/v03-browser.js`。模型测试仍覆盖 150 人队列与通关规则，但这不代表 150 人新美术已实现或通过视觉验收。

## 已知限制
- 真实 iPhone/iPad Safari、底栏实际收缩、安全区域及多指缩放待真机人工测试，不能由 Chromium 模拟代替。
- 插画方向、局部细节、年龄差异和人物辨识度均待人工确认；不把生成成功等同于美术验收通过。
- PNG 保留原始质量，资源总量和首次加载成本较高；这是视觉验收包，后续可在风格确认后优化资源格式/分辨率。
- Phaser 仍存在原有构建包体积提示。
- 本分支没有改 Pages 工作流，不合并 main，不运行公开部署。

## GitHub Pages 自动部署
部署配置位于 `.github/workflows/deploy-pages.yml`；合并到 `main` 后，每次推送都会用 Node.js 24 执行 `npm ci`、`npm test`、`npm run build`，全部成功后上传 `dist` 并部署。也可在 Actions 中手动运行工作流。并发部署排队，避免同时发布。

Vite 的 `base` 固定为 `/Find-face-game/`，适配本仓库的项目站点子路径（大小写一致）。本地开发也应打开开发服务器下的 `/Find-face-game/`。改名或使用自定义域名时，需要重新检查此配置。

仓库管理员需手动完成以下设置，本配置不会修改仓库可见性或自动启用 Pages：
1. 在 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
2. 确认仓库允许 GitHub Actions 及工作流使用的官方 actions；若组织策略限制工作流令牌或 OIDC，需由管理员授权所声明的 `pages: write` 与 `id-token: write`。
3. 检查 `github-pages` 环境的部署分支规则允许 `main`；如设置了审批，部署时由审核人批准。
4. 若仓库为私有仓库，先确认账号或组织套餐支持私有仓库 Pages；不支持时由仓库所有者决定升级套餐等方案，不应自动将仓库公开。私有仓库的 Pages 站点访问范围也需由管理员确认，不能假定它自动为私有。
5. 合并部署 PR 后查看 Actions 运行结果，并使用部署输出的实际 URL 验证页面、头像与两关交互。尚未执行远端 Pages 部署时，不代表站点已上线。

此工作流只部署静态构建产物，不公开 Vite 开发服务器。真实 Pages 权限、组织策略和首次部署结果需在 GitHub 上确认。
