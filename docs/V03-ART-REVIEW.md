# V0.3 · 分阶段视觉验收

本分支只提交第一阶段：10 个独立插画资源与可运行第一关。
不能将自动化测试通过当作美术通过。第一阶段人工确认前不生产 30～40 人样板或 150 人全集，不将旧 SVG 作为 V0.3 正式美术补位。

## 第一阶段请确认
- 插画画风、头身比例、五官细节、人物差异是否接近正式参考。
- 人物大小、墙体填充、前后遮挡是否合适，脸部及标志物是否清晰。
- 手机截图顶部、人物区及 5 个目标是否完整，目标卡片能否准确匹配。
- 当前资源是 AI 生成的原创独立 PNG 插画，同一风格参考下逐人生成，不是从人群整图切割。可能存在局部解剖、线条或风格不一致，需要人工审查。
- 资源还不是经人工确认的最终美术；不得把本阶段截图等同为 150 人效果已经达标。

## 文件规范与接入
- 路径：public/art/v03/character-001.png … character-010.png。
- 后续：character-011.png … character-150.png；唯一 ID 永久保留，不重复映射同一图片。
- 透明 RGBA PNG，建议 1024×1280，完整头发/帽子在画布内，肩膀延伸到底部，中胸裁切。
- 正面/轻微侧面统一透视，眼睛水平线约 45%～48% 高度，脸部中心约 (50%,52%)。任何非标准资源必须单独标注 face 元数据。
- 禁止编号、字母、水印、背景、外部投影；人物服装内部不得有无意透明洞。
- 游戏使用原始纵横比；目标栏和人物墙共用 src/characters.js 的相同文件，不单独绘制替代头像。
- 更换文件无需修改 Round 玩法模型；更换脸部锚点或比例需修改角色 manifest 并重跑命中与视觉检查。
- src/art-layout.js 独立保存第一关人群构图，以脸部锚点定位、按深度排序，身体可被前景覆盖。
- Phaser 使用 alphaTolerance=96 的逐像素透明命中，默认 topOnly 只选择最前方不透明人物；透明图片矩形不拦截后方角色。完成标记无交互。
- 美术来源及生成提示见 public/art/v03/README.md。

## 后续两阶段
第一阶段确认后，另做 30～40 人布局样板，提交真实截图与每角色可见命中区域统计。在短屏上比较角色宽度、露出面部尺寸及可点击像素，而不是无限缩小。

第二阶段确认后才扩展 150 人。固定手机视野若无法同时提供可辨识脸部与可操作面积，先交付不同人数/尺寸的测量报告，请求选择方案；不自行减正式人数，也不偷偷缩小。
例如 320×568 屏幕在扣除控制/目标栏后，若人物区约 300×350，则 150 人平均每人仅约 700 平方 CSS 像素（等面积边长约 26px，尚未扣除空白）。这只是面积上限估计，不是 150 人可用性的验证结论。需要实际样板测量。

## 真实设备待测
本环境只能运行 Chromium 自动化和截图，不能宣称真实 iPhone Safari 已验收。需人工测试 Safari 地址栏展开/收起、安全区域、横竖切换、触摸误选、多指缩放和长时间游玩。
本分支不修改 Pages 工作流、不合并 main、不调用发布。

## 本次实测记录（第一阶段）
- npm test：11/11，包括保留的 150 人规则模型回归和新增 10 张 PNG 的真实文件、分辨率、唯一哈希、可复现构图检查。
- 生产构建通过；保留原有 Phaser 大包警告。
- 四种 Chromium 触摸视口均完成两批 10 人，合计 40 次正确点击。验证精确目标 ID 标记、相同资源、错误反馈、暂停、重开、视口变化及返回菜单。
- 对每个角色的中心面部区域采样 11×11 点，结合实际 PNG alpha 和前后深度计算可见率：下表所有角色的受检不透明面部采样点可见率均为 100%。这不是整张人物图片可见率，也不能代替视觉确认。
